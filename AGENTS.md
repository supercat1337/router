# AGENTS.md

Internal guide for AI assistants editing `@supercat1337/router`. Read this before touching `src/`, `tests/`, `package.json`, `api-extractor*.json`, or `my.tsconfig.types.json`.

If something here contradicts `README.md`, `dist/types.d.ts`, or `etc/*.api.md`, the code wins — this file is a working checklist, not the contract.

---

## What this package is

- A **synchronous** state-relative router for SPA and SSR over a tree of JS objects.
- Public runtime API: `createMap`, `file`, `folder`, `isMap`, `isFile`, `isFolder`, `createRouter`, `redirect`, `isRedirect`, `MapValidationError`, `normalizeRRU`.
- Optional subpaths: `./adapters` (`createPathAdapter`, `createHashAdapter`), `./links` (`attachLinks`), `./guard` (`createGuardLayer`).
- Written in `.js` + `// @ts-check` + JSDoc. Public types live in `src/types.ts`. Public `.d.ts` are generated by `api-extractor` and reviewed in `etc/*.api.md`.

## What this package is NOT

- **Not** framework-bound. No React, Vue, Svelte, Solid imports anywhere in `src/`. Framework adapters are separate packages.
- **Not** async. `resolveMap` and `notFound` must return synchronously; a Promise is a diagnosed contract violation (`resolver-promise`, `notFound-promise`).
- **Not** a monorepo. One package, four subpath entries.
- **Not** a place for cross-map features. Maps are independent by design; no "global route registry", no cross-map redirects, no shared name resolution.
- **Not** a TypeScript-source project. `.js` sources with JSDoc are the norm; `src/types.ts` is the only `.ts` file allowed.

## Invariants (must not break)

These are true of the package and any edit that breaks them is wrong, regardless of tests:

1. **`Snapshot.map` is always a `RouterMap`.** Never `null`, never `undefined`. On error, `prev.map`.
2. **`Snapshot.chain` on `status: 'error'` is `prev.chain`,** not the failed attempt's partial chain. Partial lives in `Snapshot.error.partialChain`.
3. **`Snapshot.url` is a Router-relative URL (RRU),** not `location.pathname + search`. BU↔RRU happens only inside `UrlAdapter`.
4. **`navigationId` is a transaction id,** monotonic per document. Not a history position. Increments on `revalidate()` even when nothing changed. `navigate(current)` on a non-error snapshot is a no-op — no ID increment.
5. **`createRouter` throws on a failed initial transaction.** Classification (`invalid-rru`, `resolver-*`, `notFound-*`, `redirect-loop`, `getState`/`adapter.write` throw) — throw, no error snapshot. This guarantees `Snapshot.map` non-null.
6. **`navigate`/`replace` never throw on navigation outcomes** (`matched`, `notFound`, `error`). Contract violations throw in dev, become `navigationError` + error snapshot in prod. `reentrancy` — dev throws, prod returns current snapshot with no transaction/event/ID.
7. **Errors outside classification** (`getState` throw, `adapter.write` throw) propagate. No snapshot commit, no `navigationError`, no `navigationId` increment.
8. **`@internal` + `stripInternal: true`.** Anything tagged `@internal` is stripped from `dist/types.d.ts`. Dev-only methods (`getHistory`, `dryMatch`, `getActiveMap`, `resolveMapFor`, `getRedirectPath`) are `@internal` — always present at runtime, absent from public types.
9. **`src/index.js` and `src/index.d.ts` stay in sync.** `index.js` re-exports values, `index.d.ts` re-exports values + types from `types.ts`. Missing a type in `index.d.ts` hides it from `api-extractor` while IDE still sees it — silent drift.
10. **Subpath `.d.ts` must not re-export types from `./types.js`.** That produces `(undocumented)` + `_2`-alias noise in `etc/*.api.md`. Use inline `import("./types.js").X` in hand-written signatures.
11. **`src/internal/symbols.js` never appears in any `.d.ts` import chain.** Phantom brand symbols are declared locally in `types.ts`; runtime symbols live in `symbols.js` and stay invisible to `api-extractor`.
12. **Public surface is the only contract.** Tests are for behavior, types come from `src/types.ts`. Do not add exports casually — every new name becomes a semver commitment.

## Common pitfalls (battle-tested)

Things that have already caused `api-extractor` failures, test flakes, or type breakage. Don't re-learn them.

### 1. Destructuring with defaults in `createRouter` / `createGuardLayer` breaks `api-extractor`

```js
// ✗ This compiles, but `api-extractor run` fails with
//   "Internal Error: Unable to determine semantic information for declaration"
const { resolveMap, getState, adapter, maxRedirects = 10 } = options;
```

```js
// ✓ Use explicit property access + `??`
const resolveMap = options.resolveMap;
const getState = options.getState;
const adapter = options.adapter;
const maxRedirects = options.maxRedirects ?? 10;
```

The error message points at the source line of one of the variables — misleading. Fix: expand the destructuring. Both `createRouter` and `createGuardLayer` follow this pattern; keep it that way.

### 2. `process` without `@types/node`

```js
// ✗ TS2591: Cannot find name 'process'
const isDev = typeof process !== 'undefined' && process.env.NODE_ENV !== 'production';
```

```js
// ✓
/** @type {any} */
const runtimeGlobal = globalThis;
const isDev = !(runtimeGlobal.process?.env?.NODE_ENV === 'production');
```

Do **not** add `@types/node`. It drags `NodeJS.*` types into `dist/types.d.ts`, which is a browser+SSR package — Node-specific types don't belong in the public surface.

### 3. `HTMLBaseElement` not `Element`

```js
// ✗ TS2339: Property 'href' does not exist on type 'Element'
const href = document.querySelector('base[href]')?.href;
```

```js
// ✓
const baseEl = /** @type {HTMLBaseElement | null} */ (document.querySelector('base[href]'));
const href = baseEl ? baseEl.href : undefined;
```

### 4. Phantom brands — `types.ts` declares locally, `symbols.js` has runtime

`src/types.ts` starts with:

```ts
declare const FILE_BRAND: unique symbol;
declare const FOLDER_BRAND: unique symbol;
declare const REDIRECT_BRAND: unique symbol;
```

`src/internal/symbols.js` exports the **actual** symbols:

```js
export const FILE_BRAND = Symbol('spa-router.file');
```

They are different `unique symbol`s by design. Consequence: any cast from a runtime-branded object to the branded interface must go through `unknown`:

```js
// ✗ TS2352: neither type overlaps
return /** @type {RedirectResult} */ (Object.freeze({ ... }));

// ✓
return /** @type {RedirectResult} */ (
    /** @type {unknown} */ (Object.freeze({ ... }))
);
```

Why not import the runtime symbol into `types.ts`? Because `api-extractor` follows the import from `types.d.ts` back to `symbols.js` and fails with `ae-wrong-input-file-type` ("expected .d.ts"). The phantom split keeps `types.d.ts` self-contained.

### 5. `@packageDocumentation` goes in the manual entry `.d.ts`, not the `.js`

`tsc` does not carry module-level JSDoc from `.js` to `.d.ts`. Every entry point (`index.d.ts`, `adapters.d.ts`, `links.d.ts`, `guard.d.ts`) must have a top-of-file JSDoc block with `@packageDocumentation`, or `api-extractor` reports `(No @packageDocumentation comment for this package)`.

### 6. `rootDir` in `my.tsconfig.types.json` is `.`, `include` is `["src/**/*.js"]` — no `src/**/*.ts`

If `src/**/*.ts` is in `include`, `api-extractor` fails to resolve types (its TS-server pass picks up the `.ts` source next to the emitted `.d.ts`). `types.ts` is compiled transitively via the `.js` files that import it; that's enough.

`dist/types-temp/` must mirror `src/` — the entry paths in all four `api-extractor*.json` are `dist/types-temp/src/<entry>.d.ts`. Don't flatten.

### 7. Guard reentrancy: `syncInGuard`, not `inGuardCount`

If you see `inGuardCount > 0` guarding `runGuarded`, it's a regression — it blocks **concurrent** `nav.*` from outside while any guard is pending, which breaks last-write-wins. The correct flag is `syncInGuard`: set `true` only during a guard's synchronous frame, cleared before its first `await` (i.e. after the guard returns its promise). Concurrent navs then proceed, and the abort chain handles the race.

### 8. `c8 ignore next N` on defensive/unreachable code

Defensive guards (`!currentSnapshot` checks that `createRouter` makes unreachable, `!prevSnapshot` in `handleError`, aborted checks with no `await` between, etc.) should stay in code but be excluded from coverage:

```js
/* c8 ignore next 3 -- unreachable: createRouter commits initial before returning */
if (!currentSnapshot) {
    throw new TypeError('url(): no committed snapshot');
}
```

Don't chase 100% coverage on defensive code; do document **why** with a `--` comment.

## Build pipeline

```
npm run clean           shx rm -rf dist && shx mkdir dist
npm run build_esm       rollup → dist/<entry>.esm.js      (4 entries)
npm run build_esm_bundle esbuild → dist/<entry>.esm.bundle.js (4 entries)
npm run gen_types       tsc → dist/types-temp/src/*.d.ts
                        + copy manual .d.ts into dist/types-temp/src/
npm run bundle_types    api-extractor ×4 → dist/*.d.ts + etc/*.api.md
npm run build           all of the above + rm -rf dist/types-temp
```

Four `api-extractor*.json` configs, one per entry. Entry paths are always `dist/types-temp/src/<entry>.d.ts`. If you add a fifth subpath:

1. Add `src/<new>.js` + `src/<new>.d.ts` (manual, `@packageDocumentation`).
2. Add `api-extractor.<new>.json` (copy from `api-extractor.adapters.json`).
3. Add to `exports`, `files`, `build_esm`, `build_esm_bundle`, `gen_types`, `bundle_types` in `package.json`.

Do not disable `ae-forgotten-export` — the `_N`-alias noise it produces in `etc/*.api.md` is cosmetic and harmless. Do not add `@types/node`.

## Test conventions

- **`ava` v8**, `import test from "ava"`. No `describe`/`it`, no Jest globals.
- **One test = one assertion** where practical. Multi-assert tests must be justified (integration flows).
- **`t.teardown` for cleanup.** Router listeners, DOM mocks, `console.error` patches — everything that outlives the test body.
- **Files:** `tests/<module>.test.js`. Group by module, not by feature.
- **Names:** `<module>: <behavior in 3–5 words>`.
- **Helpers:** `tests/helpers/memory-adapter.js` (in-memory `UrlAdapter` with `writeCalls`, `trigger`, `setCurrent`), `tests/helpers/dom-mock.js` (`installDom`, `makeElement`). Reuse them; don't hand-roll mocks per test file.
- **Coverage target:** ~95% statements / ~85% branches. Defensive code stays uncovered via `/* c8 ignore */`.
- **Run:** `npm test` (c8 + ava). CI runs it on `prepublishOnly`.

Test invariants that must exist:

- Roundtrip: `map.match(map.url(name, params))` returns `matched`, same leaf, same `params` restricted to route keys. Wildcards excluded.
- Base-map consistency: every map exposing `publicRoutes()` returns `matched` for shared names.
- Root `/` is `notFound` with empty `chain`.
- `:name` does not match empty segment; `*` does.

## Editing rules

- **Do not add new exports** without an explicit reason. Each name is a semver commitment (`etc/*.api.md` diff is reviewed on every release).
- **Do not relax `strict`** in `jsconfig.json` or `my.tsconfig.types.json`. If a JSDoc block doesn't type-check, fix the JSDoc — don't cast to `any` to silence.
- **Do not remove `@internal`** from dev-only methods to "make them usable". They're intentionally hidden.
- **Do not touch `api-extractor*.json` or `my.tsconfig.types.json`** unless the pipeline is broken. If you must, reproduce in a clean `rm -rf dist && npm run build`.
- **Do not reformat** unrelated files. Prettier config is `.prettierrc`; diffs should be surgical.
- **`camelCase`** for files, functions, members. **`PascalCase`** for classes and types. **`#private`** for internal class fields. **No `_underscore` conventions.**
- **Commit `etc/*.api.md`** — it's the API review artifact. Diff review on PRs. Do not `.gitignore` it.
- **Commit `dist/`? No.** `dist/` is `.gitignore`d. `prepublishOnly` builds before publish.
